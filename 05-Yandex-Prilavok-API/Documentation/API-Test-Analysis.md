# Анализ тестирования API Яндекс.Прилавка

## Покрытие требований

### Добавление продуктов в набор

Endpoint: `POST /api/v1/kits/{id}/products`.

Проверялись успешное добавление одного и нескольких продуктов, увеличение количества уже добавленного продукта, ограничения количества товаров в наборе, а также реакции на невалидные значения: пустой или отсутствующий массив, неверный тип `productsList`, несуществующий или некорректный ID продукта, отрицательное/нулевое/строковое/пустое количество и значения за пределами целочисленного диапазона.

По требованиям имя набора должно содержать от 2 до 15 символов, а количество товаров в наборе не должно превышать 30.

### Проверка доставки «Привезём быстро»

Endpoint: `POST /fast-delivery/v3.1.1/calculate-delivery.xml`.

Проверялись XML-параметры `productsCount`, `productsWeight` и `deliveryTime`, в том числе допустимые значения, время работы службы и невалидные входные данные.

По требованиям служба работает с 07:00 до 21:00. Для 0–7 товаров и веса 0–2,5 кг указана стоимость 23 рубля; для 8–14 товаров и веса 2,6–6 кг — 43 рубля. Время доставки в обоих случаях составляет 25–30 минут.

### Операции с корзиной

Проверялись:
- `PUT /api/v1/orders/:id` — добавление продуктов, повторное добавление продукта, наличие товара на складе и обработка некорректных значений `productsList`, ID и количества;
- `GET /api/v1/orders/:id` — получение списка продуктов для существующей и несуществующей корзины;
- `DELETE /api/v1/orders/:id` — удаление существующей и несуществующей корзины.

## Основные дефекты

1. **Невалидные данные обрабатываются некорректно.** Для пустых, отсутствующих или имеющих неверный тип полей в ряде сценариев API возвращает успешный ответ или код, отличный от ожидаемого `400 Bad Request`.
2. **Встречаются ответы `500 Internal Server Error`.** Такие ответы зафиксированы в BUG8, BUG11, BUG15, BUG23, BUG31, BUG47, BUG48, BUG49, BUG50 и BUG51.
3. **Удаление существующей корзины не работает в проверенном сценарии.** Для валидного ID возвращается `404 Not Found`, хотя ожидался успешный ответ.
4. **Есть расхождение структуры ответа.** В BUG35 зафиксировано отличие фактического ответа `PUT /api/v1/orders/:id` от ожидаемой структуры, описанной в материалах проверки.

## Замечания к исходной тестовой документации

При подготовке портфолио сохранены исходные результаты выполнения. Ниже перечислены замечания, которые влияют на точность отдельных проверок и воспроизводимость дефектов.

- В тест-кейсах 4 и 5 для добавления продуктов в набор описание говорит о продукте с ID 30 и количестве 1, однако тело запроса содержит продукт с ID 1 и количеством 10. Результаты этих проверок не подтверждают заявленные в описании сценарии граничного значения без повторной проверки.
- В BUG55–BUG57 проверки больших значений `productsCount`, `productsWeight` и `deliveryTime` содержат дополнительные отрицательные значения в других полях XML-запроса. Это затрудняет изоляцию причины ответа API.
- В BUG35 расхождение имени поля `finalCCost`/`finalCost` следует повторно сверить с актуальной схемой ответа в API-документации перед повторным тестированием.
- В исходной книге пять идентификаторов тест-кейсов были автоматически преобразованы Excel в даты. В улучшенных материалах восстановлена нумерация `6.1`, `6.2`, `6.3`, `18.1` и `18.2`.

## Ограничения анализа

Результаты и дефекты перенесены из предоставленной тестовой документации. Повторный запуск запросов не выполнялся: идентификатор динамического стенда назначается при запуске сервера, а в текущих материалах нет активного адреса запущенного экземпляра и Postman-коллекции. Авторизация не проверялась в соответствии с заданием.
