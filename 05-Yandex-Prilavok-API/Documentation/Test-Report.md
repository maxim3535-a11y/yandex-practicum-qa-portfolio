# Отчёт о тестировании API Яндекс.Прилавка

## 1. Общая информация

**Продукт:** API Яндекс.Прилавка  
**Инструмент:** Postman  
**Тестовый стенд:** `https://{id}.serverhub.praktikum-services.ru/`  
**Документация API:** `https://{id}.serverhub.praktikum-services.ru/docs/`

Идентификатор стенда формируется при запуске сервера в Практикуме и не является постоянным.

## 2. Объём тестирования

Проверена новая функциональность API:

- добавление продуктов в набор — `POST /api/v1/kits/{id}/products`;
- расчёт возможности и стоимости доставки службой «Привезём быстро» — `POST /fast-delivery/v3.1.1/calculate-delivery.xml`;
- добавление продуктов в корзину — `PUT /api/v1/orders/:id`;
- получение содержимого корзины — `GET /api/v1/orders/:id`;
- удаление корзины — `DELETE /api/v1/orders/:id`.


## 3. Результаты

Выполнено **104 тест-кейса**:

| Статус | Количество |
|---|---:|
| Пройдено | 49 |
| Не пройдено | 55 |
| **Всего** | **104** |

Зарегистрировано **57 баг-репортов**. По исходной классификации 56 дефектов имеют критический приоритет, 1 — желательный. Все дефекты были отмечены как открытые на момент составления отчёта.

В 10 баг-репортах зафиксирован ответ `500 Internal Server Error`.

## 4. Результаты по функциональности

| Функциональность | Всего | Пройдено | Не пройдено |
|---|---:|---:|---:|
| Добавление продуктов в набор | 22 | 7 | 15 |

Лучший результат показала операция получения содержимого корзины: обе проверки завершились успешно. При удалении корзины сценарий с существующим ID завершился ошибкой `404 Not Found` вместо ожидаемого успешного ответа.

## 5. Основные проблемы

Основная группа дефектов связана с обработкой невалидных входных данных. При передаче пустых, отсутствующих, некорректных по типу или выходящих за допустимые границы значений API в ряде случаев возвращает успешный ответ, `409 Conflict` или `500 Internal Server Error` вместо ожидаемого `400 Bad Request`.

Также выявлено расхождение фактической структуры ответа с ожидаемой для операции добавления продуктов в корзину.

## 6. Заключение

По результатам тестирования новая функциональность API не готова к выпуску. Не пройдены 53% проверок, зарегистрировано 57 открытых дефектов, большинство из которых имеют критический приоритет. Отдельного внимания требуют обработка некорректных данных и корректная работа операции удаления корзины.

Рекомендуется исправить критические дефекты, повторно выполнить проверки по соответствующим сценариям и провести регрессионное тестирование затронутых endpoint'ов.
