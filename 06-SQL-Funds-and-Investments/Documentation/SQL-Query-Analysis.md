# Разбор SQL-запросов

В проекте восемь запросов. Ниже описано, на какой вопрос отвечает каждый из них и почему используются соответствующие SQL-конструкции.

## 1. Количество закрывшихся компаний

**Таблица:** `company`

**Логика:** отбираются записи со статусом `closed`, после чего `COUNT(*)` подсчитывает количество таких компаний.

**Конструкции:** `WHERE`, `COUNT`.

## 2. Финансирование новостных компаний США

**Таблица:** `company`

**Логика:** выборка ограничивается компаниями из США (`country_code = 'USA'`) категории новостей (`category_code = 'news'`). Для подходящих компаний выводится `funding_total`; результаты сортируются от большего значения к меньшему.

**Конструкции:** `WHERE`, `AND`, `ORDER BY DESC`.

**Важно:** запрос выводит сумму привлечённого финансирования для каждой подходящей компании, а не количество компаний.

## 3. Аккаунты, начинающиеся с Silver

**Таблица:** `people`

**Логика:** выбираются имя, фамилия и аккаунт сотрудников, у которых `network_username` начинается с `Silver`. Шаблон `Silver%` означает, что после указанного префикса может идти любая последовательность символов.

**Конструкции:** `LIKE`.

## 4. Аккаунты с money и фамилией на K

**Таблица:** `people`

**Логика:** одновременно выполняются два условия: аккаунт содержит подстроку `money`, а фамилия начинается с `K`. `SELECT *` возвращает все столбцы подходящих записей.

**Конструкции:** `LIKE`, `AND`.

## 5. Сумма привлечённого финансирования по странам

**Таблица:** `company`

**Логика:** компании объединяются в группы по `country_code`. Для каждой страны вычисляется сумма значений `funding_total`, после чего страны сортируются по убыванию общей суммы.

**Конструкции:** `SUM`, `GROUP BY`, `ORDER BY DESC`.

## 6. Сотрудники и учебные заведения

**Таблицы:** `people`, `education`

**Логика:** таблицы соединяются по условию `education.person_id = people.id`. Используется `LEFT JOIN`, поэтому в выборке остаются все сотрудники, даже если для них нет записи об образовании. В таком случае поле учебного заведения будет содержать `NULL`.

**Конструкции:** `LEFT JOIN`, псевдонимы таблиц.

**Особенность данных:** если у одного сотрудника несколько записей об образовании, в результате будет несколько строк с данными этого сотрудника.

## 7. Сумма сделок по приобретению компаний за наличные

**Таблица:** `acquisition`

**Логика:** учитываются только сделки с условием оплаты `cash`, совершённые с 1 января 2011 года по 31 декабря 2013 года включительно. `SUM(price_amount)` вычисляет общую сумму сделок.

**Конструкции:** `SUM`, `WHERE`, фильтрация по нескольким условиям и датам.

**Техническое замечание:** верхняя граница записана как `acquired_at < DATE '2014-01-01'`. Такой полуоткрытый интервал включает весь последний день периода, даже если `acquired_at` хранит дату и время.

## 8. Топ-10 стран по активности венчурных фондов

**Таблица:** `fund`

**Логика:**

1. Оставляются фонды, основанные с 1 января 2010 года по 31 декабря 2012 года включительно.
2. Фонды группируются по стране регистрации.
3. Для каждой страны вычисляются минимальное, максимальное и среднее значения `invested_companies`.
4. `HAVING MIN(invested_companies) > 0` исключает группы стран, в которых есть хотя бы один фонд с нулевым значением этого показателя.
5. Результат сортируется по среднему числу компаний по убыванию, затем по коду страны по возрастанию.
6. `LIMIT 10` оставляет первые десять строк.

**Конструкции:** `MIN`, `MAX`, `AVG`, `WHERE`, `GROUP BY`, `HAVING`, `ORDER BY`, `LIMIT`.

**Интерпретация:** среднее рассчитывается по значениям поля `invested_companies` у фондов страны, а не по отдельным строкам таблицы `investment`.

## Общие замечания по качеству исходной схемы

- В текстовом описании поле учебного заведения записано как `instituition`. Перед запуском запроса № 6 необходимо сверить точное имя столбца в БД.
- ER-диаграмма помечает `education.degree_type` как внешний ключ, но в предоставленном описании не указана таблица-справочник, на которую он ссылается.
- Запросы подготовлены по учебной схеме и формулировкам заданий. Без доступа к самой базе нельзя подтвердить успешность выполнения и получить числовые результаты.
