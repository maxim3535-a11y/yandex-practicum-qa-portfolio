# Объём тестирования и анализ требований

## 1. Web — веб-приложение

Источник: [требования к веб-приложению](https://code.s3.yandex.net/qa/files/requirements_web_app_1.1.pdf).

### Экран «Статус заказа»
Требования охватывают ввод номера заказа, получение данных, перенос длинных значений, цепочку статусов, отображение курьера, расчёт окончания аренды, просрочку, повторный поиск заказа и отмену до передачи заказа курьеру.

Отдельное изменение фронтенда: в цепочку добавлен пятый статус «Время аренды кончилось». В требованиях указано, что эта функция реализована только на фронтенде, а бэкенд ещё не готов; номер нового статуса в запросе — 3.

### Форма «Сделать заказ»
Проверки валидации построены по ограничениям требований:
- имя — русские буквы, пробел и дефис, длина 2–15;
- фамилия — русские буквы, длина 2–15;
- адрес — русские буквы, цифры, пробел, дефис, точка и запятая, длина 5–50; крайние пробелы удаляются при потере фокуса;
- станция метро — выбор из списка станций Москвы с саджестом;
- телефон — цифры и знак `+`, 11 символов без плюса или 12 с плюсом;
- дата доставки — начиная со следующего дня, выбор через календарь, ручной ввод запрещён;
- срок аренды — от 1 до 7 суток;
- цвет — необязательный выбор одного или двух вариантов;
- комментарий — русские буквы, цифры, пробел, дефис, точка и запятая, не более 24 символов.

## 2. Mobile — мобильное приложение курьера

Источник: [требования к мобильному приложению](https://code.s3.yandex.net/qa/files/requirements_mob_app.pdf).

Тест-кейсы сфокусированы на выделенных в требованиях блоках:
- уведомление приходит за два часа до конца срока выполнения заказа;
- проверяются текст уведомления, адрес, время и переход на вкладку «Мои»;
- проверяется доставка уведомлений при разных состояниях приложения и устройства;
- проверяется влияние системных настроек уведомлений, энергосбережения, режима «Не беспокоить», беззвучного режима и авиарежима;
- при отсутствии сети появляется окно «Отсутствует интернет-соединение», которое закрывается кнопкой «Ок»;
- приложение поддерживает только портретную ориентацию.

## 3. API — бэкенд

Источник: [требования к бэкенду](https://code.s3.yandex.net/qa/files/requirements_backend.pdf).

### Технические и общие требования
JavaScript, Node.js v12.17.0, HTTP/1.1, PostgreSQL, Sequelize и pg, логирование через Winston, документация через apidoc, REST и глобальная обработка ошибок с записью ошибок в `error.log`.

### API-сценарии из требований
- проверка доступности бэкенда и поиск станций метро;
- регистрация, авторизация и удаление учётной записи курьера;
- создание заказа с уникальным трек-номером;
- получение заказа по трек-номеру;
- принятие, отмена и завершение заказа;
- получение списка заказов с фильтрацией и пагинацией;
- получение количества выполненных заказов курьера.

### Правила вычисления статуса заказа
1. `finished = true` → `status = 2`;
2. `cancelled = true` → `status = -1`;
3. `inDelivery = true` → `status = 1`;
4. остальные случаи → `status = 0`.
